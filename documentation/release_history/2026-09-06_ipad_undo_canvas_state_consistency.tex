\title{iPad Undo Canvas State Consistency}
\date{2026-09-06}
\author{Mohammad Rahmani}

\begin{document}
   \maketitle

   \section{Problem}
   After an application-owned Undo, the visible canvas showed the restored state,
   but the next Pencil or eraser gesture could cause previously undone content to
   reappear. The application history and the long-lived internal PencilKit canvas
   state were therefore not fully isolated from each other.

   \section{Architecture correction}
   \begin{itemize}
      \item Application history remains the only Undo/Redo authority through
      \texttt{CanvasEditHistoryController}.
      \item Native PencilKit Undo registration is disabled when each
      \texttt{PKCanvasView} surface is created. The previous
      \texttt{levelsOfUndo = 0} configuration is removed because it does not
      disable registration.
      \item A dedicated \texttt{PencilCanvasHistoryRebaseController} owns
      construction and replacement of the internal PencilKit surface.
      \item A programmatic history restoration is intercepted before it is
      propagated as a normal user drawing callback.
      \item After Undo, Redo, Clear, or a new remote document load, the internal
      PencilKit surface is rebuilt from the authoritative drawing state and the
      active drawing tool is attached to the new surface.
      \item Only the internal \texttt{PKCanvasView} is replaced. The outer
      \texttt{UIScrollView}, content view, zoom, pan position, image layers, grid,
      and rulers remain part of the same editor hierarchy.
   \end{itemize}

   \section{Regression coverage}
   Automated source-level regression checks verify disabled native Undo
   registration, interception of application history restores, replacement of
   only the internal PencilKit surface, active-tool reattachment, and continued
   use of the application-owned history controller.
