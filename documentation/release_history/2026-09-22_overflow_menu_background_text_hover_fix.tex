   \begin{preview}
      \section{Bug}
      The overflow-menu item text changed to the native highlighted-text color
      while the requested light-purple background was not reliably painted.
      Earlier event-filter logic also ran before QMenu finished updating its
      active action.

      \section{Fix}
      The controller is restricted to the tab-row QMenu.  The selected item is
      styled with a light-purple background and the normal text palette color.
      Hover synchronization runs on the next event-loop turn, after QMenu's own
      mouse handling, so leaving an item clears the active action instead of
      allowing Qt to restore a stale one.  Search result views are untouched.
   \end{preview}
