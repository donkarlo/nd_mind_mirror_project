\date{2026-09-22}

   \begin{preview}
      \section{Bug}
      Previous overflow-menu mouseout handling ran inside an event filter.
      Qt invokes event filters before QMenu processes the same event, so the
      controller could clear the active row and QMenu could immediately set it
      again afterwards.  This made the highlight appear permanently sticky.

      \section{Fix}
      Hover synchronization is now queued with \texttt{QTimer::singleShot(0)}
      and therefore runs after QMenu finishes its native event handling.  The
      controller resolves the action under the real global cursor; if the
      pointer is outside an item, the active action is set to null.  Only the
      active row receives the requested light-purple background, while text
      keeps the normal palette text color.
   \end{preview}
