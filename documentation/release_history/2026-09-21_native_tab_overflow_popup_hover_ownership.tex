   \begin{preview}
      \section{Bug}
      The earlier overflow-hover controller depended on recognizing and wiring
      the internal QTabBar arrow button.  The active desktop Qt style creates
      the overflow popup without exposing a reliably identifiable arrow
      QToolButton, so the popup kept its native sticky blue active item.

      \section{Fix}
      Overflow popup discovery now happens at application event level from the
      popup itself.  A transient menu or item view is accepted only when its
      window geometry opens in the local band around the owning proxy tab bar.
      Its active/current item follows the actual global pointer and is cleared
      both on blank popup space and on leave, hide, or deactivation.  Hover uses
      the requested light purple background.
