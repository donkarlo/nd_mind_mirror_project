   \begin{preview}
      \section{Bug}
      The desktop Qt overflow popup is a QMenu.  Earlier fixes still relied on
      QMenu's active/selected action state, which can remain active after the
      pointer leaves an item.  Therefore the background could remain colored
      even after mouseout.

      \section{Fix}
      QMenu selected and mouse-over state are now ignored for painting.  A
      dedicated proxy style computes hover directly from the current global
      pointer position on every paint.  Exactly the menu-item rectangle under
      the pointer receives the light-purple background; no other item's
      background is changed.  Text, icons, disabled state and shortcuts remain
      native.  Mouse move and leave events simply request repaint, so mouseout
      immediately restores the original background.
