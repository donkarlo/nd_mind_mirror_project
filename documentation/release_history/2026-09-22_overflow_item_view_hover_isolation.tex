\title{Overflow Item-View Hover Isolation}
\date{2026-09-22}
\author{Mohammad Rahmani}

\begin{document}
   \maketitle

   \begin{preview}
      \section{Cause}
      Restricting the controller to QMenu protected Search, but the desktop tab
      overflow popup is implemented as a popup item view on this environment.
      Therefore the native item view kept its white selected text and the
      custom purple background never applied.

      \section{Fix}
      QAbstractItemView support is restored only for windows carrying the
      Qt.Popup flag and located beside the owning Pinned/Open tab row. Ordinary
      Search windows cannot match. The popup list uses one dedicated delegate
      that ignores native selected/hover state, paints exactly one hovered row
      light purple, restores every other row to the base background, and forces
      all text palette roles to black. The small popup viewport is synchronously
      repainted on every row transition and mouseout.
   \end{preview}
