\title{Large Visual Document Windowing Fix}
\date{2026-09-03}
\author{Mohammad Rahmani}

\begin{document}
   \maketitle

   \section{Problem}
   Multi-megabyte LaTeX documents could freeze the Qt GUI when Visual mode was restored or opened. The previous large-document implementation attached virtualization after the main window had already restored its session and replaced methods on individual Visual editor instances at runtime. It also used hard-coded window sizes instead of the configured values.

   \section{Fix}
   Large-document virtualization is now owned by a real \texttt{WindowedLatexVisualEditor} subclass and a pure \texttt{VisualSourceWindow} model. Windowing is active from the moment each LaTeX editor is constructed, including during session restoration. No \texttt{MethodType} runtime replacement is required.

   The Visual projection honors the configured page window and has a hard \texttt{visual\_window\_max\_chars} limit so long prose blocks cannot expand a Visual projection back to several megabytes. The user's existing two-page-above/two-page-below configuration is now used instead of the former hard-coded twenty-page values.

   \section{Structure preservation}
   Only Visual mode is virtualized. The canonical Source document remains complete, and the Structure panel continues to parse \texttt{self.\_source}, which contains the full LaTeX file. Therefore every section, subsection and subsubsection remains available in Structure even when the Visual projection displays only a small window around the active location. Selecting a distant Structure item causes Visual mode to load the corresponding source window.

   \section{Large Visual edits}
   Visual edits in large documents are spliced back into the untouched full source. Whole-document auto-formatting is skipped for the large-document Visual edit path to avoid blocking the GUI on every edit; explicit document formatting remains available separately.
